# 后期重启差异：根系吸水历史没有保存

2026-09-15。

## 原因

根系吸水通量`workspace.flux.Srt`在一个小时成功提交时更新。下一小时的土壤表面响应预测等代码仍会读取它，因此它实际承担了跨小时记忆的作用。原断点只保存状态Y与部分运行记忆，没有保存Srt；重启分配workspace时将它置零。

这解释了为什么断点加载后Y完全相同，继续求解第一小时却分岔。物理环境的差异随后进入MEND，造成微生物碳氮和累计预算的小幅差异。问题不在MEND反应公式。

## 隔离证据

从同一KT=8401接受态比较KT=8402：

| 对重启模型的干预 | 最大水头差 | 完整Y逐位一致 |
|---|---:|---|
| 不补回信息 | 24.1853 cm | 否 |
| 补回全部workspace | 0 | 是 |
| 仅补回flux组 | 0 | 是 |
| 仅补回Srt | 0 | 是 |
| 单独补回其他flux字段 | 差异仍在 | 否 |

单独替换参数、气象、step历史或derived派生量也不能消除差异。结果位于`annual_runs/restart-workspace-isolation-20260915/isolation.json`和`annual_runs/restart-flux-isolation-20260915/isolation.json`。

## 修复内容

- `src/+io/saveCompassCheckpoint.m`：保存已接受的根系吸水历史，底向上、层端点数组、单位s⁻¹，并记录它对应的KT。
- `src/beginRun.m`：在workspace重建后恢复这项历史，检查KT、数组形状和有限性。
- 旧断点没有这一信息时，保留兼容读取，但明确提示并标记其不保证连续/重启精确一致。不从诊断输出伪造缺失历史，不改写旧全年结果。

没有修改MEND方程、水热方程、根吸水规则或反应容差。新记录保存的是现有算法已经使用的信息。

## 验证范围

`verifyRootWaterRestart.m`从同一个旧8400断点为两条分支建立共同起点，运行8401后写入带根吸水历史的新断点，再比较连续分支与新断点重启分支。比较每小时完整Y，以及微生物、有机氮、DOM、无机氮和氧气状态/账本。该试验不声称补齐旧8400断点已丢失的信息，也不声称重建了原全年连续轨迹。

结果记录在`annual_runs/restart-root-history-fix-20260915/result.json`，只有其中`passed=true`才表示修复复验通过。原360小时重启失败记录继续保留。
